# Χρήσιμες εντολές κάτω από το τερματικό στο Linux

Αρκετές φορές σώθηκα λόγω ποικιλίας CLI εργαλείων κάτω από το Linux.

Είναι τόσες πολλές οι φορές που με λύτρωσαν από πανικό τα συγκεκριμένα
εργαλεία, γιατί τρελάθηκαν τα συστήματα στα καλά καθούμενα, που πραγματικά
δεν μπορώ να φανταστώ τον εαυτό μου να χρησιμοποιεί κάτι άλλο· θα τους
είμαι για πάντα ευγνώμων.

Θα προσπαθήσω να συλλέξω όλες τις εντολές είτε εδώ σαν ένα μεγάλο αρχείο,
είτε θα το χωρίσω σε ενότητες...δεν έχω αποφασίσει ακόμη.

Για την ώρα θα ξεκινήσω με διάφορες εντολές και στην πορεία βλέπω πως θα
οργανώσω το συγκεκριμένο άρθρο.

### Πώς εμφανίζουμε τα δικαιώματα αρχείων σε οκταδική μορφή;

```shell
$ stat -c '%A %a %n' *
```

Και για να εξηγήσουμε τι κάνει η συγκεκριμένη εντολή: το πρόγραμμα `stat`
μας δίνει το δικαίωμα να εμφανίσουμε διάφορα στοιχεία από αρχεία ή την
όποια κατάσταση αρχείων.

 - Για παράδειγμα, το `%A` εμφανίζει τα bits δικαιωμάτων και τον τύπο
   αρχείου σε μορφή αναγνώσιμη από τον άνθρωπο.
 - Το `%a` εμφανίζει τα bits δικαιωμάτων σε οκταδική μορφή.
 - Το `%n` εμφανίζει το όνομα του αρχείου.
 - Το αστέρι `*` είναι ουσιαστικά για να ελέγξει όλα τα αρχεία. Θα
   μπορούσαμε να ήμασταν πιο συγκεκριμένοι, λόγου χάριν, λέγοντας του να
   ελέγξει μόνο το αρχείο με όνομα `το-αρχειο-μου.txt` και το πρόγραμμα θα
   επέστρεφε τα δεδομένα για αυτό το αρχείο μόνο.

### Πώς απαλλασσόμαστε συγκεκριμένα προγράμματα από το σύστημα μας;

Αρκετές φορές είχα την λανθασμένη εντύπωση πως με την απλή αφαίρεση αρχείων
από το σύστημα μου, θα μου ήταν αρκετό για να έχω ξεφορτωθεί είτε αχρείαστα
πλέον προγράμματα είτε απαρχαιωμένα / μη εκσυγχρονισμένα, που στην ουσία
δεν είναι πλέον λειτουργικά για μένα, για τον ένα ή τον άλλο λόγο.

Οπόταν, πάμε να δούμε τον σωστό τρόπο με τον οποίο αφαιρούμε και
απαλλασσόμαστε αρχεία με τον **σωστό τρόπο**!

Θα ξεκινήσω με ένα παράδειγμα, για να γίνει τελείως κατανοητό.

```shell
$ dpkg --get-selections | grep openjdk
openjdk-25-doc                                  install
openjdk-25-jdk:amd64                            install
openjdk-25-jdk-headless:amd64                   install
openjdk-25-jre:amd64                            install
openjdk-25-jre-headless:amd64                   install
openjdk-25-source                               install
openjdk-26-doc                                  install
openjdk-26-jdk:amd64                            install
openjdk-26-jdk-headless:amd64                   install
openjdk-26-jre:amd64                            install
openjdk-26-jre-headless:amd64                   install
openjdk-26-source                               install
openjdk-7-jre-lib                               install
```

Όπως βλέπετε στην πιο πάνω εντολή, στο σύστημα μου (Debian), έλεγξα όλα τα
εγκατεστημένα προγράμματα που έχω και βλέπω πως η έκδοση `openjdk-25` δεν
μου είναι απαραίτητη.

Πώς την αφαιρώ μόνο αυτήν;

Απλά στην εντολή μας γινόμαστε πιο συγκεκριμένοι.

Δηλαδή, πλέον τρέχουμε

```shell
$ dpkg --get-selections | grep 'openjdk-25'
openjdk-25-doc                                  install
openjdk-25-jdk:amd64                            install
openjdk-25-jdk-headless:amd64                   install
openjdk-25-jre:amd64                            install
openjdk-25-jre-headless:amd64                   install
openjdk-25-source                               install
```

Ωραία! Τώρα βλέπουμε ότι έχουμε απομονώσει μόνο την έκδοση του προγράμματος
και των εξαρτώμενων του.

Το επόμενο βήμα είναι να αφαιρέσουμε την στήλη `install` από την έξοδο
αποτελεσμάτων.

```shell
$ dpkg --get-selections | grep 'openjdk-25' | awk '{print $1}'
openjdk-25-doc
openjdk-25-jdk:amd64
openjdk-25-jdk-headless:amd64
openjdk-25-jre:amd64
openjdk-25-jre-headless:amd64
openjdk-25-source
```

Με την βοήθεια του προγράμματος `awk`, έχουμε επιλέξει να τυπωθεί μόνο η
πρώτη στήλη.

Τέλος, την πιο πάνω εντολή την εκτελούμε σαν εσωτερική εντολή μιας άλλης
εξωτερικής εντολής και με αυτόν τον τρόπο απαλλασσόμαστε αρχεία που δεν
χρειαζόμαστε.

Σημείωση: Στην δική μου περίπτωση, χρησιμοποιώ το `nala` αντί του `apt`,
επειδή χρόνια ολόκληρα το `apt` δεν είχε τις λειτουργίες που οι χρήστες
είχαν ανάγκη και απ' όσο κατάλαβα λόγω γραφειοκρατίας για να αποδεχτούν να
προσθέσουν συγκεκριμένους μηχανισμούς στο πρόγραμμα, η ανάγκη της
κοινότητας γέννησε ή μάλλον καλύτερα να πω παρήγαγε το πρόγραμμα `nala` που
ουσιαστικά είναι `client front-end` για το `apt`.
